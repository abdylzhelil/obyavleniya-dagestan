## Что реализовано

- Первый экран с новым пейзажем, заголовком и двумя основными кнопками.
- Один раздел групп вместо повторяющихся блоков. Показаны Telegram, открытая WhatsApp №2 и заполненная WhatsApp №1. У заполненной группы нет кнопки вступления в заполненную группу: есть переход к открытой альтернативе.
- Новые аватары с единым белым знаком гор: синий Telegram и зелёный WhatsApp. В заполненной группе аватар визуально приглушён только CSS, оригинал PNG неизменен.
- Разделы главной: группы, категории, реклама, боты, правила и FAQ. Убраны повторяющиеся блоки преимуществ и описаний; действующие рекламные условия сохранены.
- Страницы групп получили пейзаж, новый аватар и заметную кнопку вступления до правил.
- Сделана отдельная страница скачивания аватаров.
- Для тестового dist введён data-preview=true: runtime SEO больше не заменяет noindex для открытых групп. Robots-теги в dist нормализованы; доступ владельцу сохранён.
- Страницы самих ботов не переделывались.

Пейзажи и аватары созданы генератором изображений для оформления. Это иллюстрации в фотографическом стиле, не документальные фотографии конкретных названных мест. Для веба подготовлены WebP; квадратные PNG оставлены для скачивания.

## Как продолжать

1. Сначала прочитать PROJECT_STATUS.md и первоначальный аудит.
2. Первоначальные рекламные изменения находятся в docs/review/2026-11-01-site-changes.patch; новый docs/review/2026-11-01-redesign.patch — дополнительный ТЕКСТОВЫЙ патч относительно той подготовленной версии. Проверять применимость до применения.
3. Новый текстовый патч содержит index.html, group.html, script.js, redesign.css, brand-assets.html и assets/brand/mark.svg. Он НЕ содержит бинарные файлы. Нельзя считать восстановление завершённым без них.
4. Из актуального источника Sites либо закрытой копии получить assets/brand/hero.webp, telegram.webp, whatsapp.webp, telegram.png, whatsapp.png. Путь в репозитории должен быть assets/brand/. Не публиковать неработающую страницу без изображений.
5. Изменения просмотрены владельцем пока в виде макета. Требуется просмотр реализованной версии перед публикацией основного сайта. Отдельного разрешения обновить основной GitHub пока не было.
6. При переносе на основной сайт использовать исходники, НЕ копировать noindex/Disallow и data-preview=true из dist тестовой копии.
