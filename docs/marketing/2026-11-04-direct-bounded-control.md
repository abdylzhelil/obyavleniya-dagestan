## Поручение и статус

Владелец04.11.2026 поручил: **«Также нужно сделать так чтобы ты автоматически все мог настраивать и смотреть»**, после согласия на ежедневный контроль. Это разрешение на обслуживание текущей кампании в рамках ранее выбранного теста, а не на произвольные расходы или новые платные продукты.

**Работает и проверено:**
- ReportsAPI, семь отчётов с исходными данными и расписанием.
- Чтение текущей кампании/группы/ключевых фраз/автотаргетинга через контроллер.
- Доставка команды посредством GitHub tools, без ручного Runworkflow владельцем.
- Одна реальная ограниченная правка минус-фразы, сохранение до/после и новое чтение.

**Подготовлены, но на реальной кампании пока не выполнялись:** переключение категорииNarrow и приостановка. Они покрыты локальными тестами. Не заявлять, что все возможные методы настройки уже проверены.

**Ещё не подключено:** APIМетрики с отдельнымmetrika:read; прямой учёт фактических вступленийTelegram/WhatsApp. «Автоматически всё» не означает доступ к сервисам, где нет авторизации.

### Доступные действия

1. **inspect** — campaigns.get715775801; adgroups.get5819958999 с проверкой принадлежности; keywords.get только этой кампании/группы. Возвращаетснимок иsha256revision.
2. **append_negatives** — только добавление с сохранением старых фраз. На первом тесте codeallowlist ограничен двумя конкретными фразами: «05 ru в махачкале», «сколько стоит картошка в дагестане». Общие «купить»,«продать»,«бесплатно»,названиягородов и произвольные фразы не принимаются.
3. **set_narrow** — меняет только категории автотаргетинга текущего объекта; ExactвсегдаYES, Alternative/Accessory/BroaderвсегдаNO;NarrowYES/NO. BrandOptionsне затрагиваются. В автоматическом режиме отключение допускается только по правилам ниже, включение обратно требует отдельного решения.
4. **pause** — только campaigns.suspend для715775801. В автоматическом режиме при подтверждённом исчерпании500 ₽безНДС или прямом поручении владельца остановить. Автовозобновления нет.

Новых кампаний, изменениябюджета, ставок, объявлений, географии или запуска/resume среди методов нет. Эти возможности не добавлять скрыто под видом обслуживания.

### Правила автоматических решений

- Не больше одной оптимизационной правки за показовый день. Защитная остановка при лимите — исключение.
-4ноября первая правка уже сделана. Вечером не добавлять ещё одну только потому, что запустилась первая ежедневная задача.
- Для минус-фразы нужно подтверждённое неподходящее намерение, исходный запрос/расход и запись причины. Не исключать все товарные категории. Не расширять allowlist или кодполитики самостоятельно.
- Для автоматическогоset_narrow=false выбран консервативный рабочий порог: минимум20кликов/100 ₽расхода, надёжные свежие данные воронки без результата и актуальное число вступлений владельца. Это не обещание статистической значимости. Пока Метрика не подключена и данные неясны — только рекомендация, не массовая правка.
- Текущий бюджет остаётся500 ₽на04–10ноября. Контроллер не умеет повышать его. Лимиты1000/3000 ₽по прежнему плану не являются разрешением автоматически доплатить.
- Не обещать мгновенную остановку: проверка раз в день, а жёсткое ограничение расхода должно обеспечиваться самой стратегиейДиректа.
- После завершения теста10ноября автоматические записи запрещены проверкой даты. Новые даты/режим обслуживания требуют нового решения.

## Как отправлять команду

Сначала inspect: прочитатьSHA файла, обновитьJSON черезGitHubupdate_file с уникальнымrequest_id, дождаться новогоrun/artifact. Дляпервогосозданияфайла —create_file. Не использоватьплатныйбраузер.

```json
{"action":"inspect","campaign_id":715775801,"group_id":5819958999,"request_id":"новый-уникальный-идентификатор"}
```

Для записи обязательны expected_revision из свежего снимка, issued_atUTC с часовымпоясом и возрастом≤15минут, причина10–500символов. Только фиксированныеIDs. Неизвестныеполя/действия отклоняются. Запросысо старымrevision отклоняются, чтобы не затереть чужую правку. Это оптимистическая проверка, не атомарная транзакция с интерфейсомЯндекса.

ПослеAPIзаписи контроллер повторно читаетсостояние. Артефактresult.json содержит request,before,revision,предложенныйAPIpayload,after,applied,verified,status. Без verified=true или отдельно доказанной проверки не объявлятьуспех.

Если workflowпоказалfailed иapplied=true, изменение могло уже произойти. **Не повторять запись вслепую**: inspectиразобратьafter. Поддерживается узкая канонизация Яндекса «в»→«!в» для двух разрешённыхфраз; другие операторы не стираются при сравнении.
