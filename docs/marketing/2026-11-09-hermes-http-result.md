### Якорь и сохранение UTM

В HTML главной, строка 188, найден реальный целевой элемент: `<section class="groups-section" id="groups">`; есть ссылки `href="#groups"`. Это подтверждает наличие якоря в исходной разметке, но не фактическую прокрутку браузером. Canonical главной без query — метаданные, а не наблюдавшийся HTTP-редирект.

По тексту `script.js:670–699`, `applyCampaignInvite()`:

- Требует ровно по одному значению каждого параметра: `utm_source=yandex`, `utm_medium=cpc`, `utm_campaign=dagestan_members_search_v1`. Проверка: `values.length === 1 && values[0] === campaign[key]`. Дубли одного из трех ключей, другое значение или отсутствие ключа прекращают функцию. Дополнительный `utm_content=hermes_diagnostic` не мешает этой проверке.
- Требует существования группы `telegram-main` и `group.status === "open"`. В полученных данных группа открыта.
- Для внутренних ссылок того же origin с путем, заканчивающимся на `.html` или `/`, устанавливает три UTM: `url.searchParams.set(key, campaign[key])`, затем `anchor.setAttribute("href", url.pathname + url.search + url.hash)`. Существующие прочие параметры и hash код специально не удаляет. На новые ссылки страницы группы диагностический `utm_content` этой функцией не копируется: список переносимых ключей содержит только три указанных UTM. На ссылках-якорях текущей страницы существующий query может сохраниться при разрешении URL.
- Это перенос через URL при выполнении JS, а не сохранение атрибуции в cookie/localStorage. На внешние ссылки перенос трех UTM не распространяется. Если группа отсутствует/закрыта, ранний `return` отменяет также этот перенос.
